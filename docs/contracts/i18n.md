# I18N.TERMS.V1 · 三语文案与术语

> contract_id: `I18N.TERMS.V1` · status: `CURRENT`

> 实施事实基线：`main` `678e7e4`（2026-10-02）；ST0004 在 `GLOSSARY.md` 登记衣柜术语（衣柜 · 装饰 · 穿戴 · 跟着阶段）。语言：`zh`（源）、`ja`、`en`。

## 1. 归属 Ownership

| 来源 | 拥有 |
|---|---|
| 代码里的中文字符串 | **源串**，同时是翻译键；只有中文版本写在代码里 |
| `locales/<module>.js` | 该模块源串的 `ja` / `en` 译文（`core`、`data`、`render`、`index`、`adapter`） |
| `locales/GLOSSARY.md` | 术语的唯一权威（饱食、心情、六个标签页、生命阶段……），所有译文必须使用表中词 |
| `i18n.js` | 查表与插值机制（`tr(lang, zh, vars)`） |
| `README.md` / `README.en.md` / `README.ja.md` | 面向玩家的三语说明，内容同步 |

## 2. 字段 Fields

<!-- contract:languages -->
```json
["zh", "ja", "en"]
```

<!-- contract:locale-modules -->
```json
["adapter", "core", "data", "index", "render"]
```

每个模块默认导出 `{ ja: { <源串>: <译文> }, en: { ... } }`。占位符写作 `{name}`；`{name}`（猪的名字）与 `{cmd}`（命令名）永不翻译。

## 3. 不变量 Invariants

1. **键集一致**：每个模块的 `ja` 与 `en` 键集合完全相同。
2. **占位符一致**：每条译文的占位符集合与源串相同，不多不少。
3. **数据标签全覆盖**：[GAME.RULES.V1](game-rules.md) 各表中面向玩家的 `label` 都在 `locales/data.js` 的 `ja` 与 `en` 中有译文。
4. **术语一致**：译文使用 `GLOSSARY.md` 中的词；新增术语先登记到术语表，再写译文。
5. **三语 README 同步**：改其中一份时另外两份在同一分支同步（合入门 `docs_sync`，例外需 `--docs-sync-exempt` 写明理由）。
6. 快照里的文字已按猪的语言翻译，面板不二次翻译数据标签（见 [HOST.SNAPSHOT.V1](host-snapshot.md) §4）。

## 4. 变更规则 Change rules

- **新增文案**：在代码写中文源串 → 在对应模块补 `ja` 与 `en`（契约测试会因缺键失败）。
- **改源串**：源串是键，改中文等于删旧键加新键，两种语言一起改。
- **新增语言**：本契约升 `V2`：`languages` 块、每个模块、`i18n.js` 的语言列表与 `GLOSSARY.md` 一起改。
- **改术语**：先改 `GLOSSARY.md`，再全量替换译文，合入时本文件随 `locales/GLOSSARY.md` 一起触发契约门。

- `test/i18n-core.test.js`、`test/i18n-render.test.js`、`test/i18n-adapter.test.js`：机制与渲染。
